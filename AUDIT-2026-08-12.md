# Deep Audit — `follow-the-money` (2026-08-12)

Scope: full static read of `src/follow_the_money/**`, `config/`, `schemas/`,
`prompts/`, `docs/`, plus a full `pytest` run (552 tests, **all green**).

Verdict: the codebase is well-engineered and the *deterministic* layers
(Feed validate, dedupe, schema, scoring math, claim audit, render, eval gates)
are solid. But three **production-path subsystems are non-functional or broken**,
and the green suite hides them because no end-to-end test exercises
multi-component blocks, live market-state computation, or live story-family
grouping. Severities below.

---

## 🔴 HIGH — production-path defects

### H1. Story-family / redundancy machinery is dead in production
- `events.py:158` — `build_event` sets `story_family_id = story_family_id((event_id,))`,
  i.e. **every event is forced into its own singleton family** `fam_single_<id>`.
- `resolution.py:115` `finalize_story_families` is a **no-op**: line 118 computes a
  family id and discards it, line 119 is a bare list comprehension, the function
  returns events unchanged.
- `resolution.py:123` `assign_family_ids` (which would group events by
  `_family_label`) is **never called** by `run_pipeline` (only referenced in tests).
- `selection.py:47` `distinct_first_member` is **never set to True** outside
  `tests/test_scoring.py`; in `run_pipeline` SelectionInput is built without it.
- **Mechanism:** because families are always singletons, the family-penalty loop in
  `select_events` (selection.py:117-126) never assigns a penalty, AND the
  documented `distinct_material_development` exemption (scoring.md §Selection
  step 4) is unreachable.
- **Impact:** a core selection feature — avoiding redundant coverage of the same
  story — does not run. Related events compete independently and may both be
  selected. The resilience/resolution schema supports `story_family_label` and
  `coexistence_relations`, and the golden dataset carries families, but the live
  pipeline never reads them. This is a feature that is specified, tested in
  isolation, and **absent at runtime**.
- **Fix:** wire `assign_family_ids` (populate `_family_label` from the resolver's
  `story_family_label` + `coexistence_relations`) into `run_pipeline` after
  resolution, and plumb `distinct_first_member` into `SelectionInput` from the
  validated coexistence pairs.

### H2. Market-state subsystem is dead in production
- `state.py:82` `classify_market_state` (the full 13-role / 5-dimension regime
  classifier from scoring.md and architecture.md) is **only called in tests**
  (`tests/test_state.py`). `run_pipeline` never imports or calls it.
- `pipeline.py:516-531` builds `market_state` as a **literal constant** with
  `regime: "unknown"` and every `vector` dimension `"unknown"`, then passes it
  straight to `assemble_brief`.
- **Impact:** despite an elaborate spec, the Brief's "市场状态" section **always**
  renders 未判定/未知. The decision that "regime is informational and never changes
  scoring" is moot because the regime is never computed at all. Docs/code mismatch
  + a whole implemented subsystem producing no output.
- **Fix:** compute `role_zs` / `role_return_zs` / `yield_change_zs` /
  `equity_breadth` / `surprise_votes` from the Feed's `market_data` and call
  `classify_market_state` in `run_pipeline`.

### H3. Resolver only processes `block.components[0]` → crash on any multi-component block
- `pipeline.py:344-372`: for each packed block the resolver is given the **whole
  block projection** (`_block_projection(block, aliases)` includes every
  component), but events are built only from `component = block.components[0]`
  (line 360) via `resolve_component_events(component=block.components[0], …)`.
- `resolution.py:37-66` `validate_seed_coverage` requires **every seed in the
  entire block** to be assigned exactly once across proposals/unresolved groups.
- `candidates.py:227` `pack_blocks` **deliberately packs multiple connected
  components into one block** (next-fit, up to 24 seeds / 32 KiB). So a normal
  multi-event feed produces multi-component blocks.
- **Mechanism / failure modes:**
  - If the resolver returns proposals covering all seeds (it sees the full block),
    `resolve_component_events` hits a proposal whose `event_defining_fact_ids` are
    in component[1+] → `facts` resolves empty →
    `ResolutionError("proposal references a fact not in this component")`.
  - If the resolver puts component[1+] seeds in `unresolved_groups`,
    `validate_seed_coverage` passes but those events are silently **dropped**.
- **Impact:** the normal Brief path is effectively broken for any real feed with
  more than one distinct event (the common case). This is a Blocker for live use.
  It is masked because `test_gate_13_3` uses a single news item (one component)
  and `eval_offline` replays **recorded** outputs instead of running the live
  resolver on packed blocks.
- **Fix:** iterate `block.components` (not just `[0]`) and build events per
  component, or split per-component before the resolver call; align
  `validate_seed_coverage` to the same unit.

## 🟠 MEDIUM — logic bugs / contract violations

### M1. Systemic Breadth over-counts `unclear` asset mappings
- `pipeline.py:776` `_affected_groups` returns `len(analysis.get("asset_mappings", []))`.
- Docs (scoring.md): "an affected group requires its single validated **non-unclear**
  mapping; the component is known **only when at least one mapping is non-unclear**."
- **Bug:** (a) `unclear`-direction mappings still increment the count, inflating
  Systemic Breadth; (b) when *only* unclear mappings exist, `affected_groups >= 1`
  → the component is marked **known** with a non-zero score, whereas the contract
  says it should be unknown. `merge_analysis` explicitly permits `unclear`
  mappings, so this path is reachable.
- **Fix:** count only mappings with `direction != "unclear"`; mark the component
  unknown when that count is 0.

### M2. Repricing Magnitude is permanently unknown (20/100 weight unreachable)
- `pipeline.py:781` `_observable_z` always returns `None`.
- Per `scoring.md`, Repricing Magnitude "uses the maximum observable absolute
  current-excluded reaction z among the deterministic proxies … unknown when no
  mapped proxy is observable." In v1 no reaction z is ever persisted, so this
  component is **structurally always unknown**, silently disabling a full 20% of
  the significance weight and capping significance at ~80.
- **Impact:** not a crash, but a documented "live" component is effectively a
  placeholder; the ceiling on significance is lower than the contract implies and
  not flagged as such. Should be documented as a v1 limitation or implemented.

### M3. Test coverage gap masks the above (systemic)
- The 552-test suite passes but does **not** exercise: multi-component blocks in
  `run_pipeline` (H3), market-state computation (H2), or live family grouping/
  penalty (H1). Each HIGH defect is therefore invisible to CI. Recommend targeted
  integration tests with a 2+ event Feed that produces multi-component blocks and
  asserts (a) no ResolutionError, (b) non-unknown market state when market_data
  is present, (c) family penalty actually applies / exempts on
  `distinct_material_development`.

## 🟡 LOW — dead code / config drift / no-ops

- **L1.** `pipeline.py:491` — bare dict comprehension
  `{a["event_id"]: a for a in analyses}` (no assignment): dead expression
  statement; looks like a lost `analysis_by_event = …` binding.
- **L2.** `resolution.py:115-120` `finalize_story_families` is a no-op (see H1);
  `state.py:36-48` `DimensionVote` dataclass is unused (`classify_market_state`
  uses the local `_dimension` helper instead).
- **L3.** `audit.py:65-72` — `_collect_rendered_claims` returns the inventory's own
  `claim_id`s, so the "rendered assertion outside inventory" check compares the
  inventory against itself and can never fire. The stated guarantee is enforced
  elsewhere (byte comparison at render/bundle time per the comment), but this
  branch is a no-op.
- **L4.** `config/model.py:240` `family_penalty` is never read; `select_events`
  uses the hardcoded `PENALTY = "15"` (selection.py:28). Minor config/code drift.
- **L5.** Freshness age uses `brief_generated_at` (pipeline.py:724/729) while
  `scoring.md` defines it as `evidence_cutoff_at - fully_known_at`. Minor
  doc/code mismatch (both ≈ same instant).
- **L6.** `audit.py:149-150` — any `language-audit` finding category not in the
  `critical`/`warning` lists is treated as `critical` (fail-closed, safe, but can
  cause surprising publication blocks if categories evolve without a config bump).

## What is genuinely solid (no action needed)
- Feed semantic validation, numeric/canonical guards, intelligence-field rejection
  (`feed/validate.py`).
- Conservative dedupe + strict-chronological observation handling (`feed/dedupe.py`).
- Scoring/Decimal math, market formulas, claim lexicon audit, render escaping,
  and the exhaustive golden-day offline eval gates (`eval_offline.py`) — these are
  high-quality and fail-closed.
- Provider HTTP layer correctly raises (no silent swallowing) and enforces
  HTTPS/host allowlists (`providers/http.py`).
